# Domain docs

This is a single-context repository.

## Before exploring

Read root CONTEXT.md for domain terminology and relevant decisions
in docs/adr/.

If these do not exist, proceed silently. Do not flag their absence
or propose creating them upfront. The domain-modeling skill creates
them lazily as terminology and decisions are resolved.

## Vocabulary

Use the terminology defined in CONTEXT.md in issues, proposals,
hypotheses, and tests. Note genuine glossary gaps for domain-modeling.

## Architectural decisions

Explicitly flag proposals that contradict an existing ADR rather
than silently overriding it.
